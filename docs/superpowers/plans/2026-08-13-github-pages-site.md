# GitHub Pages Site for Council Meeting Topics — Plan

> **Status: PLAN ONLY — not implemented.** Written 2026-08-13 at Caden's request.
> Prerequisite work (done same day): the Tuesday `preview-agendas` CI run, which
> produces `upcoming/<date>-<body>/agenda-preview.md` + `event.json` before each
> meeting and archives the preview into `meetings/<slug>/` afterward.

**Goal:** A public website where the main page is a plain-language ("layman's
terms") summary of the topics coming up at each upcoming Huntsville City
Council meeting, with a browsable history of past meetings' topics, votes, and
transcripts underneath.

**Non-goal:** Changing the pipeline's LLM-free guarantee. The scraping/parsing
pipeline stays deterministic; the one LLM step (plain-language rewriting) is an
isolated, optional layer whose output is committed as ordinary data files.

## Data already in the repo (site inputs)

| Input | Produced by | Feeds |
| --- | --- | --- |
| `upcoming/<slug>/agenda-preview.md` + `event.json` | Tuesday `preview-agendas` run | Main page (upcoming meetings) |

## Architecture (recommended)

**Static site generated by a small Python script, deployed to GitHub Pages via
Actions.** No Jekyll, no JS toolchain — the repo is already a typed Python CLI
with tests, so the generator should be more of the same:

- `scripts/build_site.py` — walks `upcoming/` and `meetings/`, renders HTML
  from the JSON/markdown inputs into `_site/`. Pure functions (data → HTML)
  unit-tested like the rest of the repo. Single self-contained CSS file,
  mobile-first, no client-side JS required for v1.
- Markdown → HTML: `markdown` PyPI package (or keep summaries as
  pre-rendered HTML fragments from the generator and avoid the dep).
- Deploy: `actions/upload-pages-artifact` + `actions/deploy-pages` in a
  `pages.yml` workflow triggered on push to `main` (every Tuesday/Friday
  sync commit automatically republishes) plus `workflow_dispatch`.
- Repo setting: Pages → Source = GitHub Actions. Site lands at
  `https://caden-helbling.github.io/hsv-city-council-transcripts/`
  (custom domain optional later; a `slayden-*.duckdns.org` CNAME would work
  but GitHub Pages is its own host — no homelab dependency, which is the point).

Rejected alternatives: Jekyll (fights the repo's Python idiom, weak at
consuming `votes.json`/`meeting.json`), a JS SSG like Eleventy/Astro (new
toolchain for a small site), hosting on the homelab (this content is exactly
what free static hosting is for; keep thinku's Caddy out of it).

## Page structure

1. **`/` (main page)** — one card per upcoming meeting (from `upcoming/`):
   date/time/location, the plain-language topic summary (see below), and
   collapsed-by-default full topic list from `agenda-preview.md`, with links
   to the agenda PDF and Legistar. If no upcoming agenda is published yet,
   say so ("next regular meeting is Thursday …, agenda usually posts
   Tuesday"). Below the upcoming cards: reverse-chronological list of recent
   past meetings linking into the history.
2. **`/meetings/<slug>/` (one page per past meeting)** — topics (from the
   archived `agenda-preview.md`), votes table (`votes.json`: item, result,
   ayes/nays, consent-agenda flag), links to notes.md (rendered), captions,
   Whisper transcript, audio release asset, and the official PDFs.
3. **`/meetings/` (history index)** — table of all meetings: date, body,
   #items, whether minutes/votes/transcript exist. Fine as one page for years
   at ~26 meetings/yr; paginate only if it ever matters.

## The layman's-terms summaries (the one LLM step)

- New artifact: `upcoming/<slug>/summary.md` (and archived alongside the
  preview into `meetings/<slug>/`): 3–8 bullet points in plain language —
  "The city is deciding whether to rezone 505 acres near Bob Wade Ln for
  housing" rather than "Ordinance No. 26-495…". Front-matter or a fixed
  header marks it as AI-generated with the generation date.
- Generation options:
  - **(a) Claude in the Tuesday workflow (recommended):** after
    `preview-agendas`, a step runs `claude -p` (or a small script against the
    Messages API) with `ANTHROPIC_API_KEY` as a repo secret. Input =
    `agenda-preview.md` (already parsed/compact, ~5–10 KB); output =
    `summary.md`, committed by the same job. Cost: one small call/week.
    Prompt lives in the repo (`scripts/prompts/laymans-summary.md`) so it's
    versioned and testable.
  - (b) Generate locally (claude-local on slayden / Claude Code session) and
    push — zero API cost but the site goes stale when nobody runs it. Keep
    as fallback; the workflow step should skip gracefully when the secret or
    file is absent, so the site builds either way.
- The site renders `summary.md` when present and falls back to the
  deterministic topic list when not — the LLM layer is additive, never a
  build dependency.
- README framing: the *pipeline* stays LLM-free; summaries are a labeled,
  optional presentation layer (same status notes.md already has).
